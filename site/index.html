offline developer tool / local Git history

Before you delete code, ask why it exists.

whyfence turns a file range into cited local history, changed-test signals, explicit references, and a conservative removal-risk flag. A diff gets a deterministic summary while history recovery is still range-only.

The fence is the evidence

History is the missing context.

Diffs show what changed. whyfence helps recover the local history behind a targeted range before that context disappears.

01

Point at a range

Give the CLI an inclusive file range for history recovery, or pass a unified diff when the change is the thing you have.

--range path:start-end
02

Recover local signals

For ranges, Git line history supplies commit citations. whyfence keeps explicit references and same-commit Go test paths attached to each citation.

git log -L
03

Choose with context

A deterministic low, medium, or high flag reflects only recovered range evidence. It is a caution signal, not a safety guarantee; diff input has no risk flag yet.

--report report.html

No package registry required

Run it from a clean checkout.

whyfence uses Go 1.23.0, Git, and the standard library. Docker is the reproducible offline check.

setup + first report
git clone https://github.com/sujal-suhaas/whyfence.git
cd whyfence
go test ./... -count=1
go run ./cmd/whyfence \
  --range cmd/whyfence/main.go:26-32 \
  --report report.html

Keep the claim small

Evidence is useful because it is bounded.

Range input

Recovers local commit history, explicit references, changed Go test paths, and an evidence-backed risk level.

Diff input

Accepts and summarizes files and hunks. It does not claim recovered history or risk yet.

Always local

No GitHub API lookup, ownership inference, runtime-impact measurement, or live report updates.
