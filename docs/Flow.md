# Flow

## Current CLI flow

The CLI entry point sends parsed arguments to `runWithInput`. `--version` writes
the pinned development version and returns success. `--help` is handled by the
standard flag package. Input, evidence, and report-write failures are
deterministic non-zero errors.

For a range, `runWithInput` calls `input.ParseRange`. The validated request then
calls `evidence.RecoverLineRange`, which resolves the repository root, runs
local `git log -L`, parses and de-duplicates full-hash/subject citations, and
attaches supported or explicitly `unclassified` references from each subject.
The collector runs a root-safe
local `git diff-tree` query for each recovered commit, filters repository-
relative paths whose basenames end in `_test.go`, sorts them, and attaches them
to the originating citation. The complete citation set goes to `risk.Evaluate`.
The CLI then writes stable terminal output or maps the request and citations to
`report.Data` for deterministic standalone HTML. A named report is atomically
written and produces only a stable confirmation.

For a diff, `runWithInput` calls `input.ParseDiffSource`. The validated request
is formatted as a stable source/file/hunk summary. No local history is queried,
so diff terminal output and diff reports do not contain recovered evidence or a
risk claim.

The smoke and contract tests call the same CLI functions directly. Fixture
tests create temporary repositories with fixed identities and dates. The
generated-fixture regression harness compares known expected reasons and emits
`recovered N of M` as a regression count, not a real-repository accuracy score.
Docker builds the module, runs `go test ./...`, and CI repeats those core checks
with networking disabled.

## Current static-site flow

The landing page is checked in under `site/` and uses only local HTML/CSS plus
relative links to checked-in demo/report artifacts. The report gallery is made
of snapshots generated by the CLI from pinned repository commits; opening the
page does not invoke Git or a remote API. On a push to `main`,
`.github/workflows/pages.yml` checks out the repository, configures the
workflow-backed Pages site, uploads `site/`, and deploys it without a build
step. The Go/Docker test workflow remains separate.

Update this map whenever execution crosses a new file, function, or deployment
boundary.
